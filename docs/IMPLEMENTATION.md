### 2.3 패널

- 패널 연도 = 공시 기준연도 − 1 (수치가 직전 회계연도 실적, `acntgYr`로 교차 확인).
- **운영 타임라인 해석 (선행성의 정확한 의미):** 브랜드-연도 t의 피처는 **t+1년 공시**
  (회계연도 t 실적 수록)가 접수된 시점에 계산 가능하고, 라벨(t+1년 실적의 악화)은 **t+2년
  공시**로 확정된다. 즉 은행이 공시를 받아 점수를 산출한 시점 기준으로 **약 1년 앞의 악화
  전환**을 예측하는 구조다. 피처와 라벨은 서로 다른 공시(정보집합)에서 나오므로 시점이 겹치지
  않으며, 이 정렬은 15125490의 `acntgYr = 공시연도 − 1` 필드와 독립 API 간 가맹점수 일치율
  98.9%로 데이터 차원에서 교차 검증했다. 연 1회 공시의 시의성 공백은 LLM 뉴스 층이 메운다
  (점수 미투입, 화면 표시 전용).
- 매출 0/미기재 → 결측(행 유지). 상하위 1% winsorize(연도별 횡단면).
- **0점포 아티팩트 처리**: 직전연도 10개+ 브랜드가 당해 0으로 보고된 558행은 공시 미기재·재등록
  아티팩트로 판정해 결측 처리(적대적 리뷰 확정 결함 수정 — 412→0→395 같은 원복 사례 다수).
- **직영점수·지역분산 병합**: 15125490의 `areaNm='전체'` 행 → 직영점수(병합률 84.4%),
  17개 시도 행 → 진출지역수·지역HHI·최다지역비중(전체 54.8%, **학습에 쓰이는 자격 표본에서는
  96.1%**). 전체 병합률이 낮은 이유는 소규모·단명 브랜드가 지역 공시를 남기지 않기 때문이고,
  실제 모형 표본(점포 30+·3년 연속)에서는 거의 결측이 없다.
  ⚠️ '전체'와 지역 행을 합산하면 정확히 2배 중복 → 분리 사용. **독립 API 간 가맹점수 일치율 98.9%**.
- **등록취소 병합**: 접수연도 기준 241행 매칭(자진 154 / 직권 87).
- **실시간 표본 자격**(적대적 리뷰 수정): `eligible_t` = [t까지 누적 최대 점포수 ≥ 30] AND
  [t에서 끝나는 연속 관측 ≥ 3년] — 과거 정보만 사용.

**✅ M1 DoD:** 생존성 진단표 출력, 라벨 표본 3,635행(수백 건 이상), 양성률 9.2% (목표 10~30%
대역 하단 근접 — 완화 조건 미사용, 확장 트랙은 별도 공개).

### 2.4 가맹본부 재무 — 금융감독원 전자공시(DART) (`src/dart.py`)

**왜 추가했는가.** 여기까지의 피처는 전부 *브랜드의 겉모습*이다(가맹점 수·평균매출·계약종료율).
그런데 브랜드가 무너지는 실제 경로는 대개 **본부가 먼저 무너지는 것**이고, 본부 부실이 가맹점
지표로 나타나기까지 1~2년이 걸린다. 즉 본부 재무는 브랜드 지표보다 **앞서는** 신호다.
공정위 집계 API 에는 이 정보가 아예 없다.

**흔한 오해 정정 — "DART 는 상장사만"은 사실이 아니다.** 외부감사 대상 법인은 비상장이어도
감사보고서를 DART 에 제출한다. 실측으로 메가엠지씨커피(앤하우스)·컴포즈커피·이디야·BHC·
배스킨라빈스·더벤티·굽네치킨·본죽 등 주요 **비상장** 본부가 모두 4년치 감사보고서를 내고 있었다.
상장사만 세면 커버리지가 가맹점 가중 4.7% 지만, 감사보고서까지 포함하면 39.7% 가 된다
(자격 브랜드·가맹점 수 가중, `outputs/dart_match_report.json` 이 매 실행마다 재측정한다).
최종 수집: 재무 2,759건 / 법인 562개, 재무상태표 항등식 통과율 99.6% · 손익 정합 98.3%.

**그러나 DART 만으로는 여기가 천장이다.** 외부감사 대상이 아닌 본부는 애초에 제출 의무가 없다.
미확보분을 분해해 보니 가맹점 가중 60.3%p 중 **50.9%p 는 법인명이 DART 인덱스에 아예 없었다** —
매칭을 더 잘해서 해결되는 문제가 아니라 원천에 문서가 없는 것이다.

**그래서 두 번째 원천을 붙였다 — 공정위 정보공개서(`src/ifrmp_web.py`).** 정보공개서에는 외감
여부와 무관하게 전 등록 브랜드의 3개년 본부 재무가 실려 있다. 전량 자동 수집은 캡차로 막혀
있고 **우회하지 않으므로**(§9 한계), 점포 수가 많은 브랜드부터 사람이 직접 열람해 받았다.
받는 순서는 `tools/ifrmp_wanted.py` 가 한 건당 커버리지 기여로 정렬해 준다.

| 단계 | 처리 | 안전장치 |
|---|---|---|
| 파싱 | 열람 본문/PDF → 재무 6항목 + 신호 19종 | 열 위치를 **고정 오프셋으로 가정하지 않고** 머리글에서 읽는다 |
| 브랜드 확정 | 문서의 등록번호·영업표지 **후보**를 패널과 대조 | 확정 못 하면 **버린다** — 남의 재무를 붙이는 것은 없는 것보다 나쁘다 |
| 검산 | 자산 = 부채 + 자본 (상대 1%) | 위배 시 해당 문서 전체 폐기 |
| 결측 | 전 항목 0 인 연도행은 **미기재로 간주해 제외** | 0 으로 저장하면 '매출 0 인 정상 본부'가 만들어진다 |
| 통합 | `merge_into_hq()` → `hq_financials.parquet` | 같은 (법인, 연도)는 **DART 우선**(감사의견·계속기업 주석이 함께 있다) |

⚠️ 이 통합 단계가 없던 동안 **수집분이 어디에도 쓰이지 않았다.** `ifrmp_web_financials.parquet`
를 읽는 곳이 우선순위 목록 도구 하나뿐이어서, 사람이 받아 온 브랜드를 모형도 화면도 본 적이
없었다. '수집했다'와 '쓴다'는 다른 말이다. 지금은 `run_pipeline.py` 의 `ifrmp` 단계가
**dart 다음·features 앞**에서 합친다(순서가 바뀌면 합친 행이 날아가거나 모형이 못 본다).

**파서를 독립 원천으로 검증했다.** 두 원천이 같은 (법인, 회계연도)를 갖는 구간이 7쌍
있다 — 한쪽은 금감원에 접수된 감사보고서, 다른 쪽은 사람이 열람 화면에서 옮긴 정보공개서다.
이 구간의 재무 6항목을 대조하면 **42개 값 전부 0.1% 이내 일치**한다(최대 상대차 6.4e-07,
정보공개서가 천원 단위로 반올림된 데서 오는 차이). 즉 "우리 파서가 맞다"를 우리 주장이
아니라 **제3자가 감리한 문서**로 말할 수 있다. 이 대조는 `tools/check_doc_numbers.py` §⑥-3
이 매 실행마다 다시 계산하며, 하나라도 어긋나면 실패한다.

**현재 커버리지 — 모형이 실제로 본 양.** 자격 브랜드 **13.8%** · 가맹점 가중 **48.1%**
(DART 단독 39.7% → 정보공개서 열람 법인 **28**개 추가). 이 두 값은 수집량이 아니라
`features.parquet` 의 `f_hq_has_financials` 에서 직접 재며, `tools/check_doc_numbers.py` §⑥-3
이 매 실행마다 산출물에서 재계산해 이 문서와 대조한다.

**핵심 설계 — 이름으로 붙이지 않는다.**

| 단계 | 방법 | 실측 |
|---|---|---|
| ① 후보 생성 | 법인명 정규화(법인격 토큰 **먼저** 제거 → 구분기호 제거) | FTC 법인 19,928개 → 후보 1,674건 |
| ② 확정 | 공정위 원천의 `brno`(사업자등록번호)·`crno`(법인등록번호)를 DART `company.json` 의 `bizr_no`·`jurir_no` 와 **대조** | **확정 700 / 불일치 812** |
| ③ 수집 | 상장·사업보고서 제출사는 구조화 API(`fnlttSinglAcntAll`), 그 외 외감법인은 `list.json`→`document.xml` 감사보고서 원문 파싱 | 두 원천 중 **더 완전한 쪽을 통째로** 채택 |
| ④ 검산 | 자산총계 = 부채총계 + 자본총계 항등식 | 위배 행은 재무상태표 값 폐기·건수 보고 |

②가 이 모듈의 존재 이유다. **이름 매칭의 54%가 틀렸다.** 검증 없이 붙였다면 절반 이상의
브랜드에 남의 재무제표가 들어갔을 것이다. 구체적 사례:

- (주)한국일오삼(처갓집양념치킨) → 같은 이름의 다른 법인에 매칭 (FTC 2148720528 vs DART 5348703724)
- **(주)우리개발** → DART 에 같은 이름의 법인이 **7개**. 사업자번호가 맞는 것은 단 하나.

**파서 검증.** 실제 감사보고서 3건으로 계정 6종 × 3사 = 16개 값이 원문과 정확히 일치함을 확인했고,
3건 모두 회계 항등식이 성립했다. 라벨은 문서마다 `자산총계`/`자 산 총 계` 처럼 공백이 섞여 있어
**글자 사이 공백을 허용**해야 한다(이디야 보고서가 후자 — 이를 놓치면 부채비율이 조용히 결측된다).

**정성 신호의 오탐 제거.** 초기 구현은 정상 기업 3곳 모두를 위험으로 표시했다.

| 신호 | 잘못된 방법 | 실제 구현 |
|---|---|---|
| 감사의견 | 본문에서 "적정의견" 문자열 검색 | 변형의견 전용 **제목**(한정의견·부적정의견·의견거절)을 먼저 확인. "적정의견이 표명되었습니다"는 *전기 타감사인* 언급이라 오탐 |
| 계속기업 불확실성 | "계속기업" 등장 여부 | 회계감사기준 570 의 별도 제목 `계속기업 관련 중요한 불확실성` 존재 여부. "계속기업"은 모든 보고서의 상투구 |
| 자본잠식 | 본문에 "자본잠식" 언급 | **숫자로 판정**(자본총계 < 자본금 → 부분, ≤ 0 → 완전). 문자열은 주석의 *피투자회사* 잠식까지 잡음 |

**신규 피처 15종**(`f_hq_*`): 자기자본비율·부채비율·영업이익률·순이익률·ROA·매출로그·매출성장률·
연속적자연수·영업손실·자본잠식·자본잠식(완전)·계속기업의문·재무확보여부·결산노후도.

⛔ **시점 안전**: 패널 연도 t 의 피처는 **회계연도 ≤ t−1** 만 쓴다. 회계연도 t 를 써도 형식상
누출은 아니지만(감사보고서는 t+1년 3~4월 접수, 공정위 t년 통계도 t+1년 공개), 두 공시의 시차가
해마다 흔들릴 수 있어 한 해 더 물렸다. 결산이 3년보다 오래되면 아예 붙이지 않는다.
누출 테스트는 본부 재무 표를 **별도로 교란**해 검증한다(패널만 교란하면 이 피처들이 검증
범위 밖으로 조용히 빠진다 — 과거에 실제로 겪은 사고).

### 2.5 정보공개서 원문 — 공정위 가맹사업정보제공시스템 (`src/ifrmp.py`)

집계 API 가 주는 것은 숫자 몇 개지만, 정보공개서 원문에는 **그 숫자의 근거 문서 자체**가 있다.
실제 문서 1건에서 표준 코드 섹션 **110개**를 확인했고, 여신 심사에 직접 쓰이는 것은
본부 3년치 재무상황·3년치 점포 유출입(연초/신규/계약종료/해지/명의변경/연말)·지역별 평균매출
(상하한·3.3㎡당)·공정위 시정조치 이력·민사소송·형의 선고·계약 갱신거절 사유·계약 해지 사유다.

**실측으로 확정한 두 가지 사실:**

1. **HTTP 406 은 키 문제가 아니라 WAF 다.** `franchise.ftc.go.kr` 은 `User-Agent` 헤더가 없으면
   `406 Access denied` 를 반환한다. UA 를 붙이면 200 이 온다. (앞서 이를 키 문제로 오진해
   "정보공개서 API 는 별도 키가 필요해 접근 불가"로 결론냈던 것을 정정한다 — 별도 키가 필요한
   것은 맞지만, 406 의 원인은 키가 아니었다.)
2. **공개 데모키(`sampleKey`)는 본문을 고정 1건만 준다.** `type=list` 는 실제 데이터를 주지만
   페이지당 1건이고, `type=content` 는 `jngIfrmpSn` 을 무엇으로 주든 **항상 같은 문서**를 준다
   (sn 149646·150572·150958·152502·151420 → SHA-256 전부 동일, 3,722,374자, 놀부 흥부찜닭).

따라서 `sampleKey` 로는 "브랜드별 정보공개서를 파싱했다"고 말할 수 없다. 모듈은 서로 다른 sn 의
**응답 해시를 대조해 데모 고정응답을 스스로 탐지**하고, 그 경우 브랜드별 산출물을 만들지 않는다
(`outputs/ifrmp_status.json` 의 `is_demo: true`, `collected_brands: 0`). 파서가 옳아도 데이터가
1건이면 1건이라고 말해야 하기 때문이다.

**파서는 실제 문서로 검증했다** — 재무 3개 연도 6개 계정 전부 원문 일치, 점포 표 3개 연도 6개 열
전부 일치, 위험 섹션 3종 '해당사항 없음' 정확 판정. 정식 키(`IFRMP_SERVICE_KEY`)가 들어오면
같은 코드가 즉시 전량 수집으로 전환된다.

> 참고로 이 데모 문서 자체가 본 프로젝트 논지의 교과서적 사례다. 놀부 흥부찜닭은 자본총계가
> 264.7억 → 57.6억 → 6.1억으로 잠식되고 영업이익이 +1.2억 → −40.9억으로 꺾인 **다음 해에**
> 가맹점이 132개 → 92개(−30%)로 줄었다. 본부 재무가 브랜드 지표에 선행한 실제 관측이다.

### 3.2 라벨

  초변동성이 임계값을 왜곡하지 않도록. 판정 시점 이전 정보만 사용해 실시간 안전.

기준 LightGBM Lift@10% **2.500 > 기준모형 최고 2.167** → 통과.
플랜B 불필요(단, 검정력 보강 결과도 함께 공개 — README ②).

보정 관련 수정 ①: isotonic 계단으로 보정확률이 소수 값으로 붕괴해 상위 10% 경계에 대규모 동률이
생기던 결함(리뷰 확정)을 원점수 순위 tie-break로 해소하고, 보정 점수 기준 지표를 metrics.csv에 추가.

보정 관련 수정 ② — **확률 상·하한**: isotonic 은 계단함수라 양 끝이 검증표본의 경험률로 포화된다.
실측에서 보정확률이 정확히 **1.000(3행)** 과 **1.4e-08(하위 830행)** 까지 나왔고, 대시보드에는
"P(악화 전환) 100.0%"가 그대로 표시됐다. 1년 악화확률 100%·7천만분의 1은 수십 건의 검증 관측이
뒷받침할 수 있는 추정이 아니며, `EL = exposure × 악화확률 × LGD` 를 통해 손실 추정까지
과신하게 만든다. 여신 실무의 **PD 하한 관행**(바젤 IRB 0.03%)을 준용해 `config.evaluate.prob_floor=0.0003`,
`prob_cap=0.99` 로 클립한다. **단조 변환이라 순위는 바뀌지 않으므로** Lift@k·Precision@k·PR-AUC·
ROC-AUC 는 그대로이고, 과신만 억제되어 Brier·EL 에만 반영된다(EL 94.5억 → 94.9억으로 보수화).

### 4.1 워크포워드 집계 방식 — 실측으로 발견한 결함과 수정

fold별 OOS 예측을 모아 **원점수 전역 상위 10%** 로 Lift를 계산하던 초기 방식에서,
LightGBM의 풀링 Lift(2.150)가 **모든 개별 fold 값(2.62 / 2.25 / 2.50)보다 낮은** 모순이 나왔다.
원인은 fold마다 모형을 재학습하므로 **출력 확률의 스케일이 fold마다 다르다**는 것이다
(LightGBM 최대확률: 2021 fold 0.80 / 2022 fold 0.84 / 2023 fold 0.57).
그 결과 2023 fold는 행의 35.9%를 차지하면서 전역 상위 10%의 4.4%만 차지했다
(**편향배수 0.12**, 1.0이 중립). 이 방식은 재학습 모형에 불리하고 매년 같은 변환을 쓰는
고정공식 기준모형(persistence·단일변수)에 유리한 인위적 편향을 만든다.

수정: 상위 k% 지표는 **fold 안에서** 계산한다.
- `macro_avg_folds` — fold별 지표의 단순평균. **주 지표**
  (운영 의미: "매년 상위 10%를 점검하면 얻는 리프트". 은행은 연도를 섞어 한 줄로 세우지 않는다.)
- `pooled_oos_rank` — fold 내 백분위로 정규화 후 풀링 (스케일 드리프트 제거)
- `pooled_oos_raw` — 결함이 있는 원래 방식. **삭제하지 않고 함께 공개**하고,
  진단 근거를 `outputs/walkforward_pool_bias.csv` 에 수치로 남긴다.

부트스트랩도 같은 원칙으로 바꿨다: 연도블록을 재표집한 뒤 **fold 안에서 Lift를 계산해 평균**한
값의 차이를 본다. 세 집계 모두에서 결론은 같다 — LightGBM은 persistence를 유의하게 이기고,
단일변수·로지스틱과는 통계적으로 동등하다.

## 4.2 전제 검증 — 브랜드 공통요인 상관 실증 (`src/correlation.py`)

이 프로젝트는 "같은 브랜드에 묶인 여신은 브랜드라는 공통 요인으로 상관된다"는 전제 위에 선다.
전제가 거짓이면 브랜드 단위 관리 자체가 불필요하므로, **주장하지 않고 측정**했다.

**식별 전략.** 한 브랜드의 점포는 여러 시도에 흩어져 있고 시도마다 상권·경기·임대료가 다르다.
점포 감소가 지역별로 독립이면 입지 요인, 여러 지역에서 동시에 일어나면 브랜드 요인이다.
15125490(브랜드×연도×지역 가맹점수) 144만 행에서 지역별 전년 대비 감소 사건을 만들고,
같은 브랜드-연도 안의 지역쌍이 **함께 감소할 확률**을 실측했다(지역쌍 349,089개).

**측정.**
1. 사건상관 ρ_e = (p11 − p²) / p(1−p)
2. **자산상관 ρ_a** — 단일요인 가우시안에서 p11 = Φ₂(Φ⁻¹(p), Φ⁻¹(p); ρ) 를 ρ에 대해 수치 역산.
   바젤 IRB/ASRF와 **같은 정의**이므로 규제 가정값과 직접 비교된다.
3. 층화로 공통충격 제거 — "그냥 코로나 아니냐"는 반론을 수치로 반박하기 위해
   연도·업종 층 안에서 기준확률을 따로 잡는다. 층 전체를 움직인 충격은 기준확률에 흡수된다.

**결과 (자산상관).** 통제없음 0.418 → 연도통제 0.417 → **연도+업종통제 0.416** [0.382, 0.438].
거시·업종을 걷어내도 거의 변하지 않는다 → **브랜드 자체가 공통 요인**임이 확인된다.
바젤이 기업여신에 가정하는 12~24%의 **1.7~3.5배**. 전 지역 동시감소는 독립 가정 대비 **21.6배**.

**브랜드 *간* 상관은 별도로 잰다 (층위 이중계상 방지 — 자체 감사 지적 반영).**
ρ_W 는 *한 브랜드 안에서 지역끼리*의 상관이다. 브랜드 1개를 채무자 1행으로 집계한 뒤 이 값을
브랜드 *사이* 상관으로 쓰면 이중계상이 된다(집계 시 내부 상관은 이미 ρ=1로 소진). 그래서
브랜드 단위 악화율의 **연도 간 변동**에서 ρ_B 를 따로 역산했다(부도율 시계열 적률법):
**ρ_B = 0.005** [0.000, 0.009]. 연도별 악화율이 0.53~0.62로 안정적이라 거시 공통요인은 사실상
검출되지 않는다 — 위험이 **경기가 아니라 브랜드에 있다**는 뜻이고, 브랜드 단위 관리라는 처방을
오히려 강화한다.

**브랜드를 무시한 대가.** 은행 여신은 브랜드 법인이 아니라 개별 가맹점주에게 나가므로,
차주를 개별 노드로 두고 브랜드를 중간 계층으로 갖는 **2단계 요인 모형**으로 계산한다
(`X_ij = √ρ_B·Z + √(ρ_W−ρ_B)·Y_i + √(1−ρ_W)·ε_ij`, 예시 포트폴리오 60개 브랜드 9,180 차주,
몬테카를로 20만 회). 요인이 주어지면 브랜드 내 차주는 조건부 독립이므로 이항분포로 한 번에
뽑아 정확히 계산한다. 결과: 99% 손실 14.9억 → 21.7억(**+6.8억, +45.6%**),
비예상손실 1.7억 → 12.7억으로 **7.69배**. 차주 9천 명을 독립으로 보면 대수의 법칙이 작동해
비예상손실이 거의 사라지지만, 브랜드로 묶이면 그렇지 않다는 것이 이 수치의 의미다.

**추정기 검증(허수아비 방지).** 실데이터 결과가 그럴듯해 보인다고 믿지 않고, **정답을 아는
합성 데이터**로 추정기 자체를 검증한다(`tests/test_sanity.py::correlation_math`):
① 자산상관 역산 왕복 오차 <1e-3 ② 독립 데이터에서 ρ≈0(거짓 양성 없음) ③ 심어둔 ρ=0.30 복원
④ **거시충격만 있는 데이터에서 층화가 0.142 → 0.003 으로 제거** ⑤ 손실 시뮬레이션 재현성·단조성.

**한계(명시).** 관측 단위는 '지역 내 가맹점 수 감소'이지 차주 부도가 아니므로 ρ는 부도상관의
대리지표다. 비교 대상인 바젤 자산상관도 관측이 아닌 규제 가정값이다. exposure는 합성이므로
절대 금액이 아니라 **독립 가정 대비 배수**가 메시지이며, 배수는 exposure 스케일에 불변이다.

### 5.1 LLM 뉴스 신호

  다시 검증**한다(기사 인덱스 범위·enum 소속 재확인 — 스키마를 통과해도 인덱스는 틀릴 수 있다).

  **재시도 없이 즉시 폴백**(같은 입력이면 결과가 같으므로 쿼터 낭비를 막는다).
  사고(thinking) 파트는 응답에서 제거해 **모델 내부 추론이 메모로 새지 않게** 한다.
- 안전 필터는 `BLOCK_ONLY_HIGH` — 입력이 '소송·부도·집단폐점' 같은 부정적 기업 뉴스라
  기본 임계값에서는 정상 기사가 유해로 오탐되어 분류가 통째로 막히는 일이 있다.
  차단되더라도 예외로 올려 규칙 폴백으로 내려앉으므로 무방비가 아니다.
- **점수 미투입** (`config.llm.score_injection: false`) — 화면·메모 표시 전용.
- **실동작 검증**: 키 없이도 HTTP 경계만 모의로 치환해 스키마 정제·사고파트 제거·차단·절단·
  재시도·키미설정·인덱스 재검증까지 전 경로 검증(`tests/test_llm_paths.py` 4/4).
  실키 연결은 `python check_keys.py --llm` 이 모델 목록 조회 + 실제 코드 경로 1회 호출로 확인한다.
  로그는 의도가 아니라 **실제 LLM 추출 건수/폴백 건수**를 분리 보고(오도 로그 결함 수정 반영).

### 5.2 포트폴리오 집중·상관
- **여신 exposure는 공정위 공시 창업비용(15110265) 실측값에서 유도**한다:
  exposure = 가맹점수 × 브랜드별 창업비용 × 대출조달비율(0.6) × 은행 점유율(0.15).
  창업비용·가맹점수는 실측(예시 포트폴리오 60/60 브랜드 확보, 점포당 중앙값 79.4백만원)이고
  뒤의 두 비율만 가정이다. 실제 여신 잔액은 은행 내부 자료라 공개 데이터에 존재하지 않는다.
  은행 내부 실행 시 `config.portfolio.exposure_source` 에 CSV 경로만 넣으면 실여신으로 전환된다.
- 집중도: 브랜드별 exposure·상위10 비중 65.1%·HHI 0.070.
- 상관 손실 `EL = exposure × 악화확률(보정) × LGD{0.3,0.45,0.6}`,
  스트레스(상위 10% 악화확률×1.5, cap 1.0). ⚠️ 악화확률은 PD 가 아니다 — 부도가 아니라
  공시 기반 구조악화 전환의 확률이므로 EL 도 '부도 기대손실'이 아닌 **대리 손실 지표**다.
- 위험등급은 **순위 기반**(값 임계 컷이 동률과 충돌해 High가 설계 10%→29%로 부풀던 결함 수정).
- 헤드라인: 총 여신 697억원 → LGD 45% EL 14.5억원, 스트레스 16.0억원. 위험등급 High 6/60.

### 5.3 심사메모 + RAG (COULD)
- 입력(SHAP 상위요인 + 공시 수치 + 뉴스 + **RAG 검색 근거**)만 인용하도록 시스템 프롬프트 제약.
- **프롬프트 인젝션 방어**: 뉴스 제목은 신뢰할 수 없는 외부 텍스트이므로 그 안의 지시문을 따르지
  말라는 규칙을 시스템 프롬프트에 명시(리뷰 지적 반영).
- 필수 고지("2선 리스크 참고용·자동 여신결정 아님") 누락 시 강제 부착. 키 없으면 결정적 템플릿 폴백.
- **진짜 RAG**: 뉴스 + 공시 이력을 문서 코퍼스(20,117문서)로 구축, TF-IDF(단어 1-2gram +
  char_wb 2-4gram) 색인, 브랜드·위험요인 질의로 검색 → 메모에 **문서ID·출처·발행일·유사도** 인용.
  외부 임베딩 API 미사용으로 키 없이 완전 재현.

## 9. 알려진 한계 (심사 정직성)

1. **여신 익스포저는 공시 창업비용 기반 추정치** — 가맹점수·창업비용(15110265)은 실측이고
   대출조달비율 60%·은행점유율 15%만 가정이다. 실여신 잔액은 은행 내부 자료라 공개
   데이터에 없다. `config.portfolio.exposure_source` 에 CSV 경로만 채우면 실여신으로 교체된다.
2. **브랜드 악화 → 개별 차주 부도 연계 미검증** — KB 내부데이터 PoC 항목(기획서와 동일 범위).
3. **정보공개서 원문 — 파서 완성·전량 수집 대기** — 공개 데모키가 본문을 고정 1건으로만
   반환함을 코드가 스스로 탐지한다(§2.5). 정식 키가 들어오면 즉시 전량 수집.
4. **관리번호 미확보 2.2%** — 명칭 기반 ID 사용, `id_source` 컬럼으로 출처 표기.
5. **LightGBM 우위 범위** — persistence 대비 유의(+0.788, CI [0.413,1.195]), 강한 기준모형
   2종과는 통계적 동등. "압도적 우위"를 주장하지 않으며 부트스트랩 CI를 함께 공개.
6. **확장 표본에서는 LightGBM 열위** — 업종 혼합이 트리 모형에 불리. 숨기지 않고 공개.
7. **2021년 표본 단절** — 공시 등록 급증(직영점 요건 완화). 업종×연도 분위수가 부분 흡수.
8. **LLM 라이브 호출 미실행** — 개발 환경에 API 키 없음. 실제 코드 경로는 모의 API로 검증했고,
   키 설정 시 즉시 동작. 로그·화면에 실제 LLM 사용 건수를 정직 표기.
9. **뉴스 소스 라이선스** — Google News RSS는 개발 보조용. 상용 시 계약 피드 대체 권장.
