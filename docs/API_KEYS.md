# API 키 등록 매뉴얼

> **키가 없어도 전 화면이 돈다.** 원본 스냅샷(`data/raw/`)과 산출물(`outputs/`)이 저장소에 함께
> 들어 있어, 새로 클론해서 `streamlit run src/app.py` 만 해도 모든 화면이 실제 수치로 뜬다.
> 키는 **지금 막혀 있는 기능 하나를 여는 것**이지 앱을 켜는 조건이 아니다. 그래서 급할 것 없고,
> 필요해지는 순서대로 하나씩 넣으면 된다.

---

## 0. 한눈에

| 키 | 발급처 | 걸리는 시간 | 없을 때 (지금 상태) | 넣으면 |
|---|---|---|---|---|
| **`DART_API_KEY`** | opendart.fss.or.kr | 5분 · 즉시 발급 | 비적정 감사의견이 **'원문 확인 필요'** 로만 표시 | 감사보고서 원문을 다시 읽어 의견을 확정 |
| **`DATA_GO_KR_KEY`**<br>+ 데이터셋 15081808 활용신청 | data.go.kr | 10분 · 승인 반영에 수십 분 | 일괄 조회의 **'사업자 상태'** 가 빈칸 | 차주 사업자번호로 국세청 계속·휴업·폐업 확인 |
| `GEMINI_API_KEY` (선택) | aistudio.google.com | 5분 | AI 상담이 **표로** 답변, 뉴스는 규칙기반 추출 | 문장 답변 + 뉴스 사건 LLM 추출 |
| `NCP_API_KEY_ID` / `NCP_API_KEY` (선택) | NAVER API HUB | 15분 | 검색수요 미수집, 뉴스는 제목만 | 검색수요 지표 + 뉴스 본문 요약 |
| `IFRMP_SERVICE_KEY` (선택 · 난이도 높음) | 공정위 가맹사업정보제공시스템 | 별도 심사 | 본부 재무는 DART 수집분만 | 전 등록 브랜드의 3개년 재무 (→ 기술설명서 §8-4) |

**권장 순서: DART → 공공데이터포털 → (여유 있으면) Gemini → 네이버.**
앞의 두 개가 "기능이 하나 꺼져 있는" 항목이고, 뒤의 두 개는 "지금도 대체 경로로 도는" 항목이다.

## 1. 키를 넣는 곳

### 1-1. 로컬 — `.env` 파일

저장소 **맨 위 폴더**(`config.yaml` 과 같은 자리)에 `.env` 파일을 만들고 한 줄에 하나씩 적는다.

```
DART_API_KEY=여기에받은키
DATA_GO_KR_KEY=여기에받은키
```

- 따옴표 없이, `=` 앞뒤에 공백 없이 쓴다.
- `.env` 는 `.gitignore` 에 들어 있어 **커밋되지 않는다.** 확인은 `git check-ignore -v .env`.
- 이미 떠 있는 앱·터미널은 파일을 다시 읽지 않는다 — **앱을 껐다 켠다.**

### 1-2. 배포 — Streamlit Community Cloud

share.streamlit.io → 해당 앱 → **⋮ → Settings → Secrets** 에 TOML 형식으로 넣는다.

```toml
DART_API_KEY = "여기에받은키"
DATA_GO_KR_KEY = "여기에받은키"
```

저장하면 앱이 자동으로 다시 뜬다.

우선순위는 **환경변수 > `.env` > Streamlit Secrets** 다(`src/common.load_secrets`). 이미 값이 있는
이름은 덮어쓰지 않는다.

> ⚠️ **공개 앱에 `DATA_GO_KR_KEY` 를 넣으면 방문자가 내 키 할당량을 쓴다.** 일괄 조회 화면에서
> 사업자번호를 올리는 사람마다 국세청 호출이 나가기 때문이다. 시연이 필요할 때만 넣고, 평소에는
> 로컬 `.env` 에만 두는 것을 권한다. DART 키는 화면이 호출하지 않으므로 배포에 넣을 이유가 없다.

## 2. DART 키 — 감사의견 원문 대조

**왜 필요한가.** 본부 재무의 `audit_opinion` 은 감사보고서 원문에서 자동 판독한 값이다. 초기 판독기가
문서 전체에서 '의견거절'·'한정' 같은 단어를 주워 담아 최신연도 본부의 약 15%를 비적정으로 읽었다
(결함 144). 판독기는 고쳤지만 이미 만들어진 값과 캐시에는 옛 판독이 남아 있어, 화면에서는 지금
**'원문 확인 필요'** 로만 표시한다. 키가 있어야 원문을 다시 받아 확정할 수 있다.

1. <https://opendart.fss.or.kr> 에 가입하고 로그인한다.
2. 상단 **인증키 신청/관리 → 인증키 신청** 에서 이름·이메일을 넣고 신청한다. 메일 인증을 마치면
   40자리 키가 바로 발급된다.
3. `.env` 에 `DART_API_KEY=` 로 넣는다.
4. 무엇을 다시 읽을지부터 확인한다 (키·네트워크 없이 대상만 나열, 쓰기 없음).

```bash
python tools/verify_audit_opinions.py --dry-run
```

5. 실제 재판독. 원문 ZIP 을 순차로 받아 새 파서로 읽고 `data/processed/hq_financials.parquet` 를
   갱신한다. 행별 old/new 와 근거 발췌는 `outputs/audit_opinion_verification.csv` 에 남는다.

```bash
python tools/verify_audit_opinions.py
```

   종료 코드: `0` 완료 · `1` 연속 실패로 중단(그때까지는 기록됨) · `2` 키 없음.
   요청 간격은 기본 2초이고, 받은 ZIP 은 다시 받지 않는다.

6. 결과를 화면에 반영한다.

```bash
python run_pipeline.py --step diagnose
```

## 3. 공공데이터포털 키 — 국세청 휴·폐업 조회

**왜 필요한가.** 브랜드가 멀쩡해도 그 차주의 사업자등록이 이미 폐업 상태일 수 있다. 등급보다 먼저
봐야 할 사실이라 일괄 조회에 배선해 뒀지만, 키와 **데이터셋 활용신청**이 있어야 동작한다.

1. <https://www.data.go.kr> 에 가입하고 로그인한다.
2. **'국세청_사업자등록정보 진위확인 및 상태조회 서비스'**(데이터셋 번호 `15081808`)를 검색해
   **활용신청** 한다. 활용 목적을 적고 신청하면 자동 승인된다.
3. **마이페이지 → 데이터활용 → 인증키** 에서 **일반 인증키(Decoding)** 를 복사한다.
   Encoding 키를 넣어도 코드가 알아서 풀어 쓴다(`src/nts.py`).
4. `.env` 에 `DATA_GO_KR_KEY=` 로 넣는다.
5. 확인한다.

```bash
python -c "from src.nts import lookup_status; print(lookup_status(['124-81-00998'])[['b_no','status','error']])"
```

   - `status` 에 '계속사업자' 같은 값이 나오면 성공이다.
   - **'등록되지 않은 인증키(-4)'** 는 키가 틀린 게 아니라 **활용신청이 게이트웨이에 아직 반영되지
     않은 것**이다. 수십 분 기다렸다 다시 해 본다. 재발급하지 말 것.
   - **'인증키 누락(-401)'** 은 `.env` 를 못 읽은 것이다. 파일 위치(저장소 맨 위)와 이름 철자를 본다.

6. 화면에서: **일괄 조회** → 신청 목록을 올리고 **'사업자번호 열'** 선택 상자에서 해당 열을 고르면
   결과에 '사업자 상태' 열이 채워진다. 국세청 원천이 30분 주기로 갱신되므로 화면도 그 정도로 캐시한다.

## 4. 선택 키

### 4-1. `GEMINI_API_KEY` — AI 상담 문장 답변, 뉴스 사건 추출

1. <https://aistudio.google.com> → **Get API key** 에서 발급한다.
2. `.env` 에 `GEMINI_API_KEY=` 로 넣는다. 키를 여러 개 받아 `GEMINI_API_KEY_2` … `GEMINI_API_KEY_12`
   까지 넣어 두면, 무료 한도(429)에 걸릴 때 `src/llm.py` 가 순서대로 갈아탄다. 무료 한도는 **키 단위**라
   로고 판독처럼 호출이 수천 건인 작업에서는 키 수가 곧 하루 처리량이다.
3. 확인: **AI 상담** 화면에서 아무거나 물어본다. 답변 위의 "답변 생성 모델(Gemini)이 연결되지 않은
   데모라…" 안내가 사라지면 연결된 것이다.
4. 뉴스 층까지 다시 돌리려면 `python run_pipeline.py --step news`, 정답셋 대비 성능을 다시 재려면
   `--step eval_llm` 을 실행한다.

### 4-2. `NCP_API_KEY_ID` / `NCP_API_KEY` — 검색수요·뉴스 본문

1. NAVER API HUB 콘솔에서 애플리케이션을 등록하고 **검색**과 **데이터랩(검색어트렌드)** 을 신청한다.
2. `.env` 에 두 값을 넣는다. 구 개발자센터 키(`NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET`)만 있으면
   검색은 되지만 검색어트렌드는 안 된다.
3. 확인: `python run_pipeline.py --step demand` (검색수요), `--step news` (뉴스).

### 4-3. `IFRMP_SERVICE_KEY` — 정보공개서 정식 키

공정위 가맹사업정보제공시스템의 **별도 키 체계**다. data.go.kr 키로는 접근할 수 없다(해당 데이터셋의
등록 유형이 「LINK」라 포털이 자료를 호스팅하지 않는다 — 기술설명서 §8-4에 규명 과정이 있다).
받으면 외감 여부와 무관하게 전 등록 브랜드의 3개년 재무가 열려 본부 재무 커버리지가 근본적으로
해소된다. 파서와 정합은 이미 완성돼 있다.

## 5. 넣은 뒤 체크리스트

1. 앱이 키를 **실제로 보는지** 확인한다 (값은 찍지 않고 있음/없음만 본다).

```bash
python -c "from src.common import capability_report as r; import json; print(json.dumps(r()['keys'], ensure_ascii=False, indent=2))"
```

2. 관련 스텝을 다시 돌린다 (§2~§4의 명령).
3. 테스트와 문서 대조를 돌린다.

```bash
pytest -q && python tools/check_doc_numbers.py
```

4. 산출물이 바뀌었으면 **문서 수치와 한 커밋으로 함께** 올린다. 산출물만 갱신하고 문서를 두면
   `check_doc_numbers` 가 CI 에서 막는다 — 운영 설계서 §1 의 규칙이다.

## 6. 증상별 대처

| 증상 | 원인 | 조치 |
|---|---|---|
| `인증키 누락(-401)` | `.env` 를 못 읽음 | 파일이 저장소 맨 위에 있는지, 이름이 `.env` 인지, 키 이름 철자를 확인 |
| `등록되지 않은 인증키(-4)` | 활용신청이 아직 게이트웨이에 반영 안 됨 | 수십 분 기다린다. **재발급하지 않는다** |
| DART `401`·`403` | 키 오타, 또는 메일 인증 미완료 | 포털에서 키 상태 확인 |
| `INVALID_KEY` (정보공개서) | data.go.kr 키로 공정위 시스템을 부름 | §4-3 — 별도 키가 필요하다 |
| Gemini `429` | 무료 한도 소진(키 단위) | 하루 기다리거나 `GEMINI_API_KEY_2` 이후로 키를 더 넣는다 |
| 키를 넣었는데 앱이 못 봄 | 실행 중인 프로세스는 `.env` 를 다시 읽지 않음 | 앱·터미널을 껐다 켠다 |

## 7. 보안 수칙

- **`.env` 는 커밋되지 않는다.** 그래도 `git status` 에 `.env` 가 보이면 멈추고 `.gitignore` 부터 본다.
- 키를 스크린샷·이슈·메신저에 붙여 넣지 않는다. 이 저장소 코드는 키 값을 로그와 오류 문자열에
  출력하지 않는다(`src/nts.py` 는 마스킹한다).
- 노출됐다면 발급처에서 **폐기하고 다시 받는다.** 키는 지우는 것보다 바꾸는 것이 빠르다.
- 공개 앱 Secrets 에는 꼭 필요한 키만 둔다(§1-2의 경고).
