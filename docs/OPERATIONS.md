## 1. 데이터 갱신 캘린더 — 이 도구의 시계는 공시가 정한다

공정거래위원회 가맹사업 정보공개서는 **연 1회** 갱신된다. 그리고 `acntgYr = 공시연도 − 1`,
즉 **수치는 직전 회계연도 실적**이다(15125490 `acntgYr` 필드로 교차 확인, 독립 API 간
가맹점수 일치율 98.9%).

| 단계 | 시점 | 실행 | 산출물 |
|---|---|---|---|
| 수집 | 공시 반영 확인 후 D+0 | `--step collect` | `data/raw/*.json.gz` 스냅샷 |
| 정합·패널 | D+1 | `--step panel` | `panel.parquet`, `survival_report.csv` |
| 피처 | D+1 | `--step features` | `features.parquet` |
| **운영 점수** | **D+2** | **`--step score`** | **`outputs/scores_latest.csv`** |
| 포트폴리오·상관 | D+2 | `--step portfolio --step correlation` | EL·집중도·ρ 산출물 |
| 뉴스 보완 | **월 1회** | `--step news` | `news_signals.json` |

**왜 연 1회 공시로 충분한가, 그리고 왜 충분하지 않은가.** 이 모델이 예측하는 것은 분기
실적이 아니라 **브랜드의 구조적 악화 전환**이며, 그 신호(계약종료율·점포 순증감·지역 분산)는
연 단위로 축적된다. 다만 연 1회는 시의성 공백을 남기므로, 그 사이는 **뉴스 층이 보조**한다
(§5). 뉴스는 **점수에 투입하지 않는다** — 재현성과 누출 방지 원칙(`llm.score_injection: false`).

**타임라인의 정확한 의미.** 브랜드-연도 t의 피처는 t+1년 공시로 계산 가능하고, 라벨(t+1년
실적의 악화)은 t+2년 공시로 확정된다. 즉 **점수 산출 시점 기준 약 1년 앞**을 본다.
그래서 최신 코호트는 **정의상 라벨이 없다** — `--step score` 가 필요한 이유이며, 이 코호트의
성능 근거는 과거 백테스트(`metrics.csv`, `walkforward_metrics.csv`)에 있다.

## 2. 산출물 → 심사역 업무 흐름

```
scores_latest.csv  ──▶  점검 큐 (grade=FS3 주의)  ──▶  심사역 확인  ──▶  조치
     │                                                      │
     ├─ factor1~3 (SHAP)  "왜 위험한가"                      ├─ 이상 없음 → 종결·사유 기록
     ├─ deterioration_rank_pct       "포트폴리오 내 상대 위치"            ├─ 추가 확인 → 뉴스·공시 원문 대조
     └─ n_stores          "규모"                             └─ 조치 필요 → 한도·조건 재검토 상신
```

**현재 실측 (2024년 코호트, `outputs/scores_latest_meta.json`):** 자격 브랜드 1,442개 중
주의(FS3) 366 / 관찰(FS2) 632 / 안정(FS1) 444. 심사역 1인이 주당 10건을 본다면 주의 등급
전량 검토에 약 **37주**다. 큐를 그대로 흘려보내면 1년이 걸린다는 뜻이므로, 운영 초기에는
**주의 ∩ 여신 익스포저 상위** 로 큐를 좁혀 시작하는 것을 권고한다.

## 3. 재학습·검증 주기와 **승인 게이트**

| 항목 | 주기 | 조건 |
|---|---|---|
| 재학습 | **연 1회** (신규 라벨 연도 확정 직후) | 아래 게이트 전부 통과해야 배포 |
| 정기 검증 | 연 1회 (재학습과 별개, 독립 수행) | 워크포워드 fold 1개 추가해 재측정 |
| 임시 검증 | 드리프트 경보 발생 시 (§4) | 즉시 |

**배포 승인 게이트 (하나라도 불통과 시 기존 모델 유지).**

1. 신규 fold의 Lift@10% ≥ persistence 기준모형 **+0.3** 이상
   — 근거: 현재 fold평균 격차 **+1.059**, 95% CI **[1.003, 1.115]** (`walkforward_delta_ci.csv`,
     연도블록 부트스트랩 200회). 더 보수적인 fold t-구간으로도 [+0.824, +1.292] 로 0 을 넘는다.
     하한보다 보수적인 값을 게이트로 잡아 우연한 통과를 막는다.
2. 신규 fold의 Lift@10% 가 직전 3개 fold 평균 대비 **−30% 이내**
   — 근거: 현재 fold별 **2.818 / 2.752 / 2.667** 로 변동폭이 ±3% 수준이다
     (`walkforward_metrics.csv`, scope=fold_test_*).
3. 시점누출·상관 테스트 6/6, LLM·RAG 4/4, **보정기 6/6** 통과
   (`python tests/test_sanity.py`, `test_llm_paths.py`, `test_calibration.py`)
4. 문서-산출물 수치 대조 통과 (`python tools/check_doc_numbers.py`)
5. 라벨 규칙·임계값 **무변경** — 변경 시 별도 승인 절차(§6)

**⚠️ 금지사항.** 성능이 나쁘게 나왔다고 라벨 임계값·표본 조건을 조정해 재측정하지 않는다.
그 조정은 §6의 변경관리 절차를 거쳐야 하며, 조정 전후 결과를 **모두** 공개한다.

## 4. 드리프트 감시

| 대상 | 지표 | 주의 | 경보 | 조치 |
|---|---|---|---|---|
| 피처 분포 | PSI (연도 간) | 0.10 | **0.25** | 경보 시 임시 검증 착수 |
| 점수 분포 | PSI (`deterioration_1y`) | 0.10 | **0.25** | 보정기 재적합 검토 |
| 실현 악화율 | 라벨 양성률 | ±3%p | **±5%p** | 라벨 정의 재검토(변경관리 경유) |
| 데이터 커버리지 | 자격 표본 수 | −10% | **−20%** | 수집·정합 파이프라인 점검 |
| 병합 품질 | 관리번호 확보율 | <95% | **<90%** | 엔티티 정합 규칙 점검 |

기준선 실측값: 라벨 양성률 9.2%, 관리번호 확보율 97.8%, 자격 표본 3,635행
(연도별 양성률 **7.9~11.8%** 는 `outputs/label_composition.csv` 에 기록).

> 이 표는 **자격 통과 표본**(3,635행)의 구성이다. 자격 필터 이전 프레임(7,163행,
> 양성률 11.4%, 연도별 10.1~12.6%)은 `label_composition_pregate.csv` 에 따로 둔다.
> 예전에는 한 파일이 자격 이전 프레임을 담으면서 범위를 밝히지 않아, 이 문서는
> 10.1~12.6% 를 인용하고 IMPLEMENTATION 은 9.2% 를 인용하는 모순이 있었다.

PSI = Σ (실제비율 − 기준비율) × ln(실제비율 / 기준비율), 10분위 기준. 기준은 **학습 train 구간**.

## 5. 경보 규칙과 뉴스 층의 역할

**등급 경보** — 등급이 FS1/FS2 → **FS3(주의)로 상향된 브랜드**는 즉시 큐에 올린다.
(`risk_grade` 의 High/Medium/Low 는 FS3/FS2/FS1 과 1:1 대응하는 하위호환 별칭이다 —
실측으로 1행도 어긋나지 않는다. 순위 컷 경로는 `grade_bands.json` 부재 시 폴백일 뿐이다.)
연 1회 갱신이므로 상향 자체가 드문 사건이고, 그래서 신호 가치가 높다.

**뉴스 경보 (보조, 점수 미투입).** 월 1회 수집해 `event_type ∈ {본부분쟁, 재무이슈, 집단폐점}`
이고 `confidence ∈ {상, 중}` 이며 **최근 12개월** 이내인 신호만 화면에 띄운다.
뉴스는 **사실관계 미확인 정보**이므로 다음을 강제한다:
- 화면·메모에 출처 URL·발행일 병기, "점수 미반영 · 사실관계 별도 확인 필요" 문구 고정
- 뉴스만으로 등급을 바꾸지 않는다. 심사역 확인 후 별도 의견으로만 반영
- LLM 추출 실패 시 규칙 폴백으로 내려가고 `llm_used=false` 로 표기 (거짓 표기 금지)

## 6. 모델 거버넌스 (MRM)

| 역할 | 책임 | 산출물 |
|---|---|---|
| 개발 | 모델 구축·문서화 | `docs/IMPLEMENTATION.md`, `docs/INTERFACES.md` |
| 검증(독립) | 재현·누출점검·성능 재측정 | `docs/LEAKAGE_CHECKLIST.md`, 테스트 결과 |
| 승인 | 배포 가부 결정 | §3 게이트 판정 기록 |
| 운영 | 배치 실행·모니터링·경보 처리 | 본 문서 §1·§4 로그 |

**독립 검증이 가능하도록 설계된 부분** — 검증자는 개발자의 주장을 믿지 않고 재현할 수 있다:
- 새 클론 + `data/raw` 스냅샷만으로 API 호출 없이 전 지표 재현 (실측 bit-identical 확인)
- 라벨 규칙·임계값이 학습 **전** git 커밋(`cfcf164`)으로 고정 — 사후 조정 여부를 이력으로 검증
- 문서 수치 **174건**이 산출물에서 자동 재계산 대조 (`tools/check_doc_numbers.py`).
  ⚠️ 이 문서(OPERATIONS.md)는 오랫동안 대조 **대상에서 빠져 있었다** — 레지스트리에는
  등록돼 있었으나 어떤 검사도 이 문서를 겨냥하지 않아 실질 검사 0건이었다. 그 사이
  위 §2·§3 의 근거 수치가 낡았다(주의 등급 145→367, fold 격차 +0.775→+1.059).
  게이트를 규정한 문서가 게이트를 안 받고 있었던 셈이다. 지금은 검사 대상이다.
- 린트 규칙·버전 고정 (`ruff.toml`, `requirements-dev.txt`)

**변경관리.** 라벨 정의·표본 조건·모델 계열 변경은 ① 변경 전후 지표 **양쪽 공개**
② 워크포워드 재측정 ③ 승인 기록을 조건으로 한다. 변경 후 결과만 보고하는 것을 금지한다.

## 7. 실패 모드와 대응

| 실패 | 탐지 | 대응 | 서비스 영향 |
|---|---|---|---|
| 공정위 API 중단·스키마 변경 | `--step collect` 실패, `check_keys.py` | 기존 스냅샷으로 계속 운영, 스키마 변경 시 `collect.SERVICES` 갱신 | 점수 갱신 지연, **기존 점수 유효** |
| data.go.kr 키 만료·트래픽 초과 | `check_keys.py` 가 원인 구분 출력 | 키 재발급(동기화 10~30분) 또는 익일 재시도 | 수집만 지연 |
| Gemini 키 실패·쿼터 초과 | `src/llm.py` 가 429/5xx 재시도 후 예외 | 규칙 폴백 자동 전환, `llm_used=false` | **뉴스·메모만 품질 저하, 점수 무영향** |
| LLM 안전정책 차단 | `finishReason` 분기 | 재시도 없이 즉시 폴백 | 동상 |
| 모델 파일 손상 | `--step score` 가 명시적 실패 | 직전 버전 롤백(git) | 점수 산출 중단 → 즉시 인지 |
| 피처 스키마 불일치 | `score.py` 가 학습 피처 결측 시 **중단** | 0으로 채우지 않고 실패시킨다 | 조용히 틀린 점수가 나가는 것을 방지 |

설계 원칙: **LLM 계층은 언제나 선택적**이다. 키가 없어도, 차단돼도, 쿼터가 나가도 파이프라인
전체는 규칙 기반으로 완주하며 점수·등급·포트폴리오 지표는 영향을 받지 않는다.

## 8. 시스템 연계 인터페이스

**입력 (은행 → 도구).** 실여신을 붙이려면 아래 계약의 CSV/테이블 하나만 있으면 된다.
현재 예시 포트폴리오의 익스포저는 **합성 난수가 아니라 공정위 공시 창업비용(15110265)
실측값**에 대출조달비율 60%·은행 점유율 15% 두 가정을 곱한 추정치다(60건 전부
`exposure_basis=disclosed_startup_cost`, `exposure_is_synthetic=false`).
실여신 CSV 가 들어오면 그 경로가 1순위로 대체되고, 어느 경로를 탔는지가
`portfolio_summary.json` 의 `assumptions.exposure.basis` 에 실제 경로대로 기록된다.

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `brand_id` 또는 `brand_mnno` | str | 브랜드 식별자 (관리번호 권장 — 리브랜딩에 불변) |
| `exposure_mkrw` | float | 해당 브랜드 가맹점 여신 합계 (백만원) |
| `n_borrowers` | int | 차주(가맹점) 수 — 2단계 상관 모형의 분모 |

**출력 (도구 → 은행).** `outputs/scores_latest.csv` — 브랜드별 `deterioration_1y`·`risk_grade`·
`deterioration_rank_pct`·`factor1~3`(SHAP 근거). 여신 시스템에는 **참고 지표**로 적재하며,
자동 승인·거절 로직에 직접 연결하지 않는다(§9 한계).

## 10. 명시적 한계

- **자동 여신 결정에 사용하지 않는다.** 전 화면·메모에 고정 문구로 고지한다. 이 도구는
  2선 리스크 관리의 **점검 우선순위**를 정하는 보조 도구다.
- 라벨은 '부도'가 아니라 공시 기반 **구조악화 전환**이다. 따라서 이 산출물을 PD(부도확률)로
  표기하거나 인용하지 않는다 — `docs/MODEL_USE_SPEC.md` §4·§5 의 금지 용도와 같은 기준이다.
  산출물 컬럼명도 `deterioration_1y` 로 두어 오독 여지를 없앴다 — 예전 이름은 `pd` 접두사를
  써서, 은행 분석가가 CSV 를 열면 명세가 금지한 바로 그 오독을 하게 돼 있었다.
